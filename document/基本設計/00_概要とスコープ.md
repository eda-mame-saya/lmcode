## 1. 目的

社内向けデスクトップ **コーディングアシスト** アプリについて、開発者が実装・レビューできる粒度で次を固定する。

* システム構成（論理・配置）
* 主要処理シーケンス（ワークスペース〜Agent〜適用）
* ローカルデータ設計
* 非機能で検討すべき項目（数値は後追記）
* 運用・配布・保守
* セキュリティ／プライバシー方針

細部の厳密さより、**方針の一貫性と実装の迷い削減**を優先する。

### 1.1 プロダクト方針（要約）

| 項目 | 方針 |
|------|------|
| 正体 | **ローカル LLM を中核にしたコーディングアシスト**（エディタ・Agent・ターミナル）。上流整理・エラーログ整理も柱に含む |
| 実運用 | **クライアント PC で現実的な速度**を第一評価軸。大規模ローカル LLM のロマンは追わない |
| モデル帯 | **10B〜26B** 程度を想定。速度優先では Gemma 4 系など 〜12B を第一候補に文書化 |
| 品質 | モデル規模より **生成失敗・幻覚・鮮度不足の削減**（検証・再試行・根拠取得・ローカル／Web RAG） |
| 運用パターン | ユーザーは **軽快／標準／深掘り**を選ぶ（**文章用・コーディング用は別**）。ハーネス細設定は標準導線に出さない |
| 切り離し | **モデル（GGUF）**と **Agent 自動実行**はパターンと独立 |
| thinking | **コーディングは原則 OFF**（ループ要因）。**文章は深掘りのみ許容** |
| オフライン | **前提にしない**。ネットなしでも編集・ローカル LLM Agent は可能な範囲で動くが、必須要件ではない |
| 生成の正 | **llama.cpp（localhost `llama-server` + GGUF）**。クラウド LLM を正の生成エンジンにしない |
| 弱点の補完 | Web／公開データ取得を許容（公式＋条件付き非公式）。機微は端末内 RAG／整理 |
| 大規模連携 | Strata 等は **限定的／非フォーカス** |
| データ正本 | 会話・設定・ソース正本は端末側。自前アプリサーバーは置かない |

詳細: [10_クライアント実運用と運用パターン_実装方針.md](./10_クライアント実運用と運用パターン_実装方針.md)  
進捗: [12_方向再整備_実施状況.md](./12_方向再整備_実施状況.md)

## 2. 対象スコープ（本基本設計）

| 区分 | 含む | 含まない／後続 |
|------|------|----------------|
| OS | **macOS**／**Windows**（方針: [08_Windows対応_実装方針.md](./08_Windows対応_実装方針.md)） | iOS / Android |
| 機能 | **S16 コーディングアシスト**（エディタ・Agent・ターミナル・多言語 WS・補完等）。運用パターン。ローカル情報整理／RAG（方針: [11](./11_ローカルRAGと情報整理_実装方針.md)） | 会議・文字起こし・カレンダー・汎用 AI チャット（S13） |
| 生成AI | **llama.cpp（`llama-server` + GGUF）**。**GGUF は同梱せずユーザーが追加**（ライセンスは利用者責任）。運用パターンが ctx／thinking 方針を束ねる（数値は見直し中） | Ollama／Gemini 等のクラウド LLM を正としない。巨大モデル前提の最適化を第一にしない |
| 外部参照 | **任意の Web／公開データ取得**（方針: [09](./09_Web参照によるAgent補完_実装方針.md)）。公式以外は条件付き | ソース全文のクラウド常時同期、自前バックエンド必須化、無制限常時 web_search |
| 言語サーバ | Dart Analysis Server（Flutter／Dart 補完）、SourceKit-LSP（Swift 補完・定義） | 他言語 LSP の本格統合（当面） |
| 保存 | **端末ローカルが正本**（`LMCode/coding_assist/` ＋ユーザー開いた WS） | Google ドライブ連携 |
| 配布 | **ワンパッケージ（インストーラ一体）を目標**（`llama-server` 同梱可。GGUF はユーザー追加） | Store 配布、差分自動更新（初期必須としない） |
| 認証 | ログイン不要（アルファ〜社内初期） | アカウント本運用は保守章で方針のみ |

## 3. 前提・制約

* 開発: Flutter（単一コードベース）。サイドカー起動は OS 側プロセス管理。
* 自前アプリサーバーは置かない（会話・設定・ソース正本は端末ローカル）。
* 生成AI は **localhost サイドカー**を基本契約とする。
* **オフライン完結は必須ではない**。必要に応じ Web 参照で Agent／支援品質を上げてよい（送信範囲はセキュリティ章）。
* コーディング用途のマシン目安: **標準は現実速度で 10B〜14B 級が回る構成**（目安 RAM 16〜32GB）。拡張で 〜26B。モデルはユーザー用意。
* 社内展開。Store 不要。署名・公証は社内セキュリティ方針に従う。
* 方向再整備に伴う **ソース全体の最適化**を機能追加と並行して実施する（[12](./12_方向再整備_実施状況.md) TODO-C）。
