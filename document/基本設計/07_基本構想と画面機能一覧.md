# 基本構想と画面機能一覧

最終更新: 2026-11-20

本ドキュメントは、**LMCode（コーディングアシスト）** の基本構想と現行画面機能の鳥瞰である。  
詳細な画面仕様は `document/詳細設計/画面/`（Sxx）、スコープの正本は [00_概要とスコープ.md](./00_概要とスコープ.md)。  
再整備の進捗は [12_方向再整備_実施状況.md](./12_方向再整備_実施状況.md)。

## 1. 基本構想

| 項目 | 内容 |
|------|------|
| プロダクト | **LMCode** — 社内向けデスクトップ・コーディングアシスト |
| 狙い | **クライアント PC で実運用できる**ローカル LLM 中核の編集・Agent・整理。オフライン完結は目的ではない |
| モデル | **10B〜26B** 想定。速度優先で 〜12B（Gemma 4 系等）。巨大モデル勝負はしない |
| 品質 | 失敗削減（検証・再試行・根拠）＋ Web／ローカル RAG。思考頼みはコーディングで避ける |
| 運用パターン | **文章／コーディング別**の **軽快／標準／深掘り**。モデル・自動実行は独立。詳細: [10](./10_クライアント実運用と運用パターン_実装方針.md) |
| 対象 OS | **macOS**／**Windows**（Swift 補完は macOS のみ） |
| 生成の正 | **llama.cpp（`llama-server` + GGUF）**。クラウド LLM は正としない。Strata 等は限定的 |
| 外部参照 | 公開データ取得を許容（[09](./09_Web参照によるAgent補完_実装方針.md)）。機微は端末内（[11](./11_ローカルRAGと情報整理_実装方針.md)） |
| データ正本 | 会話は `LMCode/coding_assist/`。ソース正本はユーザー WS。自前サーバーなし |
| 認証 | ログイン不要 |
| 配布方針 | ワンパッケージ目標（GGUF はユーザー追加） |

### 1.1 方針の要点

1. **生成エンジンはローカル** — ソースをクラウド LLM に常時送る設計にはしない。  
2. **オフラインは前提にしない** — ネットがあれば参照データを取りに行ってよい。  
3. **端末が正本** — 会話・設定・WS はローカル。Drive 等の同期は置かない。  
4. **ユーザーはパターンを選ぶ** — ハーネス細設定は標準導線に出さない。  
5. **コーディングの thinking は原則 OFF** — 文章の深掘りのみ thinking を許容。

### 1.2 ユーザーが辿る流れ（要約）

```text
起動（S16）
  → プロジェクトフォルダを開く
  →（任意）文章／コーディングの運用パターン（軽快／標準／深掘り）
  → 編集／Agent／ターミナル（自動実行は独立トグル）
  →（任意）S11／S11a でモデル・SDK 設定
  →（任意）Web 参照・ローカル RAG で根拠を補強
```

## 2. 画面と機能一覧

| ID | 画面 | 主な機能 |
|----|------|----------|
| **S16** | コーディングアシスト | **起動画面**。左メニュー／エディタ／Agent／ターミナル／多言語 WS／補完・定義／自動実行・Flutter 自動検証 等。運用パターン UI は導入予定（12） |
| **S11** | エンジン設定 | llama.cpp（ON／接続／コーディング用モデル・ctx・thinking）、Dart SDK パス。パターン導入後は ctx／thinking を詳細へ退避予定 |
| **S11a** | モデル追加 | ローカル GGUF 取り込み・表示名登録（ライセンスはユーザー責任） |

確認モーダルの見た目は [UI共通_モーダル基本系.md](../詳細設計/画面/UI共通_モーダル基本系.md)。
