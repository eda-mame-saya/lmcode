# ローカル RAG と情報整理 — 実装方針

最終更新: 2026-11-20  
上位方針: [00_概要とスコープ.md](./00_概要とスコープ.md)／[10_クライアント実運用と運用パターン_実装方針.md](./10_クライアント実運用と運用パターン_実装方針.md)  
進捗: [12_方向再整備_実施状況.md](./12_方向再整備_実施状況.md)

ローカル LLM の強み（**機微情報を外に出さない**）を活かすため、コーディング Agent と並ぶ柱として **端末内の参照・整理**を置く。

---

## 1. 目的・非目的

### 1.1 目的

1. **エラーログ整理** — 貼付／ターミナル取り込み → 正規化・要約・仮説・次アクション（原則、生ログを外に送らない）  
2. **上流工程メモ** — 要件・制約・用語・決定事項をローカル索引化し、Agent／支援から参照  
3. **WS RAG** — README・設計 md・コメント等をチャンク索引（端末内）。Web は足りないときだけ（09）

### 1.2 非目的（当面）

| 含まない | 理由 |
|----------|------|
| 自前バックエンド必須のベクトル DB サービス | データ正本は端末 |
| ソース全文のクラウド常時同期 | 06 セキュリティ |
| クラウド LLM へのログ丸投げ | プロダクト方針に反する |

---

## 2. 運用パターンとの関係

[10](./10_クライアント実運用と運用パターン_実装方針.md) の `local_rag_depth` で厚さを変える。

| 深さの目安 | 軽快 | 標準 | 深掘り |
|------------|------|------|--------|
| コーディング | 直近／開いているファイル中心 | WS 索引＋メモ | ＋ログ／上流メモ厚め |
| 文章 | 直近／キーワード | WS／メモ | 厚めのローカル参照 |

Web（09）とは役割分担する: **機微・社内・プロジェクト固有はローカル、公開の鮮度は Web。**

---

## 3. 機能スロット（導入順案）

| 順 | 機能 | 入口のイメージ | 完了の目安 |
|----|------|----------------|------------|
| R1 | エラーログ整理（要約・次アクション） | Agent ＋メニュー／貼付 | 機微パスを落とした要約が端末内で出る |
| R2 | WS 内 md／README の簡易索引＋ retrieve tool | Agent tool | 質問に対しローカル根拠が付く |
| R3 | 上流メモ（決定事項・用語）の保存と参照 | S16 内モードまたは軽量 UI | Agent が用語・制約を踏まえる |
| R4 | ログ／メモと Web の併用ルール定着 | 09＋本方針 | 送信範囲が 06 と一致 |

画面 ID の新設が必要なら、詳細設計（画面一覧）に追記する。当面は **S16 内のモード／パネル**を優先検討する。

---

## 4. データ・セキュリティ

* 索引・メモの置き場は `LMCode/coding_assist/` 配下を基本（詳細はデータ設計に追記）。  
* 外向きクエリに乗せるのは正規化後の最小情報のみ（06／09 に従う）。  
* ユーザーが「このログは外に出さない」を明示しやすいこと（既定はローカルのみ）。
