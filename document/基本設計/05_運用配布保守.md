# 基本設計：運用・配布・保守

最終更新: 2026-10-27  
社内向け。外販 SLA・マルチテナントは対象外。

---

## 1. 配布方針

| 項目 | 方針 |
|------|------|
| 形態 | **ワンパッケージ**を目標。アプリ＋`llama-server` を一体配布。**LLM の GGUF は同梱しない**（ユーザーが S11a で追加。ライセンスは利用者責任） |
| インストーラ | macOS: `.pkg`／アーカイブ等。Windows: 当面 **zip 一式**（`08_Windows対応_実装方針.md`） |
| 更新 | 初期は **フル再インストール**。差分自動更新は必須としない |
| 配置 | 社内ポータルまたはオブジェクトストレージ＋配布 URL |
| 署名 | macOS 公証等。社内セキュリティ方針に従う |
| ロールバック | 直近 N 版のインストーラを残し、旧版再インストール可能にする |

手順の実務メモは `document/配布方法/`。

### 1.1 ワンパッケージの到達段階

| 段階 | 内容 |
|------|------|
| 目標 | ユーザーが別途 Ollama を入れずに利用開始できる |
| LLM GGUF | **同梱しない**。S11a でローカル `.gguf` を取り込み |
| 非目標 | 各端末でのモデル権利保証、Store 配布 |

---

## 2. 運用体制（初期）

| 項目 | 初期（アルファ〜） |
|------|-------------------|
| 認証 | ログイン不要 |
| 連絡 | Slack 等 |
| 障害切り分け | 端末のエラー表示・再現手順を任意共有 |
| メンテ時 | 運用連絡で利用自粛 |

### 2.1 障害優先度（目安）

| 優先度 | 例 | 対応目安 |
|--------|-----|----------|
| P1 | 全社でアプリ起動不可／LLM 全滅 | 当日 |
| P2 | Agent のみ不可（エディタは可） | 数営業日 |
| P3 | 端末固有・稀な環境 | 次版 |

---

## 3. インストール後のユーザー作業（理想）

1. インストーラ実行  
2. アプリ起動（S16）  
3. S11a で GGUF を追加・コーディング用モデルを選択  
4. （任意）Dart SDK パスを設定  
5. プロジェクトフォルダを開いて利用  

Ollama インストール・`.env` 手編集は求めない。

---

## 4. サービス終了（サンセット）方針

成果物の正本は **ユーザー手元のワークスペース**。会話は `LMCode/coding_assist/`。

* ログイン不要・保証なし・完全ローカルで動く最終ビルドを社内アーカイブとして残しうる  
* アンインストールしても `LMCode/` 配下およびユーザー WS は消さない  

---

## 5. サポートで使ってよい／いけないデータ

| よい | いけない（初期） |
|------|------------------|
| アプリ版、OS、再現手順、モデル名／ctx | ソース全文・会話全文の自動収集 |
| 設定（パスを除く方針値） | 遠隔でのデータ一括削除 |
