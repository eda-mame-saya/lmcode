## 4. 生成AI（llama.cpp のみ）

### 4.1 使用 ON/OFF

| 要素 | 既定 | 備考 |
|------|------|------|
| ローカルLLMを使用する | ON 可 | OFF 時は S16 Agent 送信不可。エディタ／ターミナルは可 |

### 4.2 モデル（コーディング用のみ・ユーザー追加）

ホスト／ポートは共有。本アプリでは **コーディング用のモデル・ctx・thinking のみ**を UI に出す。  
`llama-server` は同時に **1 構成のみ**ロードする。

**GGUF はアプリ／インストーラに同梱しない。** 初回はモデル未設定。Agent 利用前に **S11a で必ず追加**する。

| UI | 用途 | 既定 |
|----|------|------|
| **コーディング用モデル**／ctx／thinking | **S16** | **未設定**／**131072（128k）**／thinking OFF。Agent自動実行は **S16 ツールバー** |

#### ユーザー取り込み（唯一のモデル源）

| 項目 | 方針 |
|------|------|
| 入口 | 「**モデルを追加…**」→ **S11a**（未設定時はここへ誘導） |
| 登録後 | ドロップダウンに表示名で追加 |
| 選択時 | コーディング用として GGUF を記憶。起動時に `--model` へ渡す |
| 未設定 | ドロップダウンは空／ヒント「モデルを追加してください」。`llama-server` は起動しない |
| 削除 | S11a の一覧から登録解除可（ディスク上の GGUF は残してよい） |
| 配置先 | `{ベース}/LMCode/local_llm/models/` |
| ライセンス | 取り込み・利用条件は **利用者自身の責任**。アプリは権利を保証しない。OSS 画面にも LLM モデル条文は載せない |

#### ロード

| タイミング | ロードするモデル |
|------------|------------------|
| アプリ起動・S11 保存後・S16 入場／設定同期 | **コーディング用**（異なれば再起動） |

* S16 のモデル変更 UI は **コーディング用のみ**を書き換える。  
* 切替時は **`llama-server` プロセス再起動**（アプリ本体は再起動しない）。  
* 正本: [S16_コーディングアシスト.md](./S16_コーディングアシスト.md)

### 4.2.1 S11a モデル追加（配下画面）

| 項目 | 方針 |
|------|------|
| 経路 | S11 →「モデルを追加…」→ `/settings/add-llm-model` |
| ファイル | **`.gguf` のみ**（file_picker）。それ以外は拒否 |
| 表示名 | ユーザー入力（空ならファイル名ステム） |
| 配置 | `LMCode/local_llm/models/` へコピー |
| ライセンス | **必須注記**: 取り込み・利用するモデルのライセンス／利用条件は **各ユーザー自身の責任**で確認・遵守すること。アプリは権利関係を保証しない |
| 操作 | 「取り込む」／「取り込んで選択する」（後者は **コーディング用**をカスタムに切替。S11 で保存すると再起動） |

### 4.3 モデル未設定時の案内

ローカル LLM が ON かつ用途のモデルが未選択のとき:

> モデルが未設定です。「モデルを追加…」から GGUF を取り込んでください。モデルのライセンス・利用条件は利用者自身の責任で確認してください。

* 赤字バナーまたはステータス文言で明示。  
* 大モデルのメモリ警告はアプリ側の固定選択肢としては出さない（ユーザー選択モデルに委ねる）。

### 4.4 接続先（ベースURL・ポート）

| 要素 | 既定 | 備考 |
|------|------|------|
| ベースURL | `http://127.0.0.1` | 手編集可。ホスト側 |
| **ポート** | **8080** | 数値入力。接続および `llama-server --port` に使用 |

| 項目 | 方針 |
|------|------|
| UI | モデルより上（使用 ON の直後）にベースURL／ポートを置く |
| 接続URL | `ベースURL + ポート`（例: `http://127.0.0.1:8080`） |
| 衝突 | 自動探索しない。失敗表示のうえポート変更 |
| 反映 | ポート変更は **`llama-server` 再起動**（モデル／ctx と同様） |

※ Ollama 既定（11434）とは別。接続先を誤ると HTTP 失敗になりうる。UI で明示する。

### 4.5 その他（llama.cpp）

| 要素 | 既定 | 備考 |
|------|------|------|
| **コンテキスト長**（コーディング） | **131072（128k）** | 起動時 `--ctx-size`。変更は再起動 |
| 選択肢 | 2048／4096／8192／16384／**32768**／**65536**／**131072（128k）**／**262144（256k）** | 長いほど KV で RAM 増。コーディングは **32GB+・128k** 目安 |
| 思考（thinking） | **OFF** | ON は遅延・空応答になりやすい。切替はサーバー再起動 |
| 接続テスト | 任意 | `/health` 等 |

Ollama ベースURL・モデル一覧更新・`ollama pull` 案内は **すべて出さない**。

### 4.6 コーディングアシスト（Dart／Flutter SDK パス）

S16 の **Dart 入力中補完**（[S16 §2.2.7](./S16_コーディングアシスト.md)）用。LLM（`llama-server`）とは独立。

| 要素 | 既定 | 備考 |
|------|------|------|
| **Dart／Flutter SDK パス** | 空 | 手編集またはフォルダ参照。空欄時は **`PATH` から `dart` を探索** |

| 項目 | 方針 |
|------|------|
| 指すもの | `dart` 実行ファイルが使える SDK ルート、または `bin/dart` を含むディレクトリ（実装は正規化して `dart` を解決） |
| 用途 | `dart language-server`（Analysis Server／LSP）の起動。S16 で WS オープン時に使用 |
| 未設定・未検出 | 補完 OFF。S16 ステータスで案内。アプリは落とさない |
| 保存反映 | **`llama-server` は再起動しない**。S16 が WS を開いている場合は Analysis Server を再起動してよい。閉じていれば次回 WS オープン時に新パスで起動 |
| 接続テスト | 任意（例: 解決した `dart --version`）。失敗時は赤字案内 |
| 関連 IF | [IF_Dart_analysis_server.md](../IF/IF_Dart_analysis_server.md) |
| 永続キー | `dart_sdk_path`（[DATA_端末設定.md](../データ/DATA_端末設定.md)） |

## 5. 保存・反映

| 操作 | 挙動 |
|------|------|
| 保存 | SharedPreferences 等へ。モデル／ctx／thinking／**ポート**／使用 ON 変更時は **`llama-server` 再起動**を試みる。**Dart SDK パス**は llama 再起動不要（§4.6）。コーディング「Agent自動実行」は S16 ツールバー（llama 再起動不要） |
| 保存〜起動確認中 | **全画面ブロッキングオーバーレイ**（半透明＋ ProgressiveIndicator）。文言例:「llama-server を反映しています…」。戻る・サイドバー操作も不可（`canPop: false`） |
| 失敗 | 設定は保存済みでも起動失敗を明示。S12 に残してよい |
| 戻る | **S10**（保存中は無効） |

## 6. 状態

| 状態 | 表示 |
|------|------|
| LLM OFF／未起動 | 赤字案内。文字起こしのみ可 |
| モデル未設定 | §4.3。S11a へ誘導。`llama-server` 起動しない |
| モデルファイル未配置 | 選択モデルが `local_llm/models/` に無い場合エラー |
| ポート衝突・待受失敗 | 該当節で赤字。ポート変更を促す（自動探索しない） |
| Dart SDK 未検出 | §4.6。S16 補完 OFF 案内（llama には影響しない） |
| 保存／再起動中 | §5 オーバーレイ |
