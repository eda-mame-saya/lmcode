## 1. 目的と位置づけ

| 項目 | 内容 |
|------|------|
| 役割 | S16 Agent（stream chat／tool） |
| 必須度 | **任意**。生成AI OFF または未起動でもエディタ・ターミナルは継続 |
| ランタイム | 同梱／展開した **`llama-server`** ＋ **ユーザー追加 GGUF** |
| API | localhost HTTP、**OpenAI 互換** |
| 認証 | なし |
| 待受 | `127.0.0.1` のみ |

## 2. コンポーネント

```text
[Flutter]
  コーディング（S16） ── LocalLlmClient 等
                               ▼ HTTP OpenAI 互換
                         llama-server（単一インスタンス）
                               │
                         local_llm/models/<選択中>.gguf
```

| 論理名 | 責務 |
|--------|------|
| `GenerativeAiGateway`／S16 Agent 層 | プロンプト組み立て・tool ループ・結果整形の入口 |
| `LocalLlmClient`（目標） | `/v1/chat/completions` 呼び出し（stream／非 stream） |
| `OllamaClient`（過渡） | 現行実装。移行注記参照 |
| `llama-server` | 単一プロセス。モデル／ctx／thinking は起動引数 |

## 3. モデル選択（同時ロードは1つ）

**本アプリの UI／ロード対象はコーディング用のみ。** 実行時にロードする GGUF は常に1つ。会議／チャット用キーが残っていても互換残置。

| 項目 | 方針 |
|------|------|
| 保存 | **コーディング用**の取り込み GGUF／表示名・ctx・thinking を保存。ホスト／port は共有。未追加は未設定 |
| 選択 UI | **S11a で取り込んだ GGUF のみ**（同梱・組み込み選択肢なし）。S11 に用途別ドロップダウン。S13 はチャット用のみ、**S16 はコーディング用のみ**変更可。未追加時は起動しない |
| カスタム配置 | `local_llm/models/<ファイル名>.gguf`。ライセンス遵守はユーザー責任（S11a 注記） |
| 起動 | アプリ起動・S11 保存後は **会議用**。S13 入場は **チャット用**。**S16 入場はコーディング用**。会議 AI 実行前は **会議用**へ戻す |
| プロセス | モデル／ctx／thinking 変更 → **`llama-server` 再起動**（Flutter アプリは再起動しない） |
| UX | 用途切替時再起動を注記（画面詳細 S11／S13／S16） |
| S16 | 多ファイル Agent・長い ctx（既定 **128k**・S11 上限 **256k**）・14B 級想定。stream ON。ツール呼び出しはアプリ側実行（詳細は S16） |

画面仕様の正本: `画面/S11_エンジン設定.md` §4.2、`画面/S13_AIチャット.md` §3.1、`画面/S16_コーディングアシスト.md`（ドラフト）。

## 4. プロセス契約

### 4.1 配置（目標）

```text
local_llm/
├── llama-server          … OS 別バイナリ
└── models/*.gguf         … ユーザー取り込みのみ（同梱しない）。両 OS 共通
```

PoC 参照: `document/llama_cpp調査/poc/`（`start_server.sh` の引数を起動契約の参考正とする）。

### 4.2 起動タイミング

| 条件 | 動作 |
|------|------|
| 生成AI ON | **アプリ起動時**に `llama-server` を起動し health を待つ |
| 生成AI OFF | 起動しない |
| 起動が極端に遅い | 遅延起動へ見直す余地あり（別途検討）。本 IF の既定は即時 |

### 4.3 起動引数（契約）

| 引数 | 既定 | 由来 |
|------|------|------|
| `--host` | `127.0.0.1` | 固定 |
| `--port` | `8080` | 既定。S11 ベースURLと整合 |
| `--model` | 選択 GGUF のパス | S11 |
| `--model-draft` | 同じディレクトリの MTP 下書き係 | ファイル名の系統が本体と一致するときだけ。`mtp-*.gguf` または `*-MTP.gguf`。会話モデルにはしない |
| `--spec-type` | `draft-mtp` | 下書き係があるとき |
| `--spec-draft-n-max` | `2` | 下書き係があるとき。12B の当たり率向けの試験値 |
| `--ctx-size` | `4096` | S11 コンテキスト長 |
| `--reasoning` | `off` | S11 思考。ON 時は `on`（または実装が選ぶ `auto`） |

その他のパフォーマンス引数は実装裁量。外部公開用オプションは付けない。

### 4.4 停止・所有

| 項目 | 方針 |
|------|------|
| アプリが起動した子 | アプリ終了時に停止。親 PID 監視を付与してよい（ASR と同型を推奨） |
| 手動起動 | デバッグ用。追随停止の対象外 |
| 設定変更 | 保存時にサーバー再起動を試みる、または次回起動反映＋ユーザー明示（S11）。**即時再起動を推奨** |

### 4.5 ポート衝突

固定 **8080**（またはユーザーが S11 で指定したポート）のみ。  
空きポート自動探索はしない。失敗を赤字表示し、S11 の **ポート**変更を促す。

## 5. 接続設定（アプリ）

| 項目 | 既定 | 備考 |
|------|------|------|
| ローカルLLMを使用する | ON 可 | OFF 時は定型 AI／S13／スケジュール AI 無効 |
| ベースURL | `http://127.0.0.1` | **手編集可**。ホスト側 |
| ポート | **8080** | S11 で独立項目。接続および `--port` |
| モデル | Qwen3.5 4B | 固定3択。GGUF 実体は同梱マッピング |
| コンテキスト長 | 4096 | 起動時適用 |
| 思考（thinking） | OFF | ON は空応答・遅延リスク（PoC） |

接続テスト（任意）: `GET /health`。

## 6. HTTP 契約

ベース: `{baseUrl}`（例: `http://127.0.0.1:8080`）

### 6.1 `GET /health`

| 項目 | 契約 |
|------|------|
| 用途 | 起動完了・接続テスト・ステータスバー |
| 成功 | HTTP 200（ボディ形は llama-server 実装に従う） |
| 失敗 | 生成AI 利用不可として案内。会議 STT は止めない |

待機タイムアウトは起動時長め／プローブ短め（数値は実装）。

### 6.2 `GET /v1/models`

| 項目 | 契約 |
|------|------|
| 用途 | 疎通確認の補助。一覧 UI の正本にはしない（モデルは同梱3択） |
| 必須 | 接続テストで使ってよい。会議フローの必須条件にはしない |

### 6.3 `POST /v1/chat/completions`（本体）

**Content-Type:** `application/json`

#### 共通リクエストフィールド

| フィールド | 必須 | 内容 |
|------------|------|------|
| `model` | ○ | ロード中モデルと整合する識別子（実装が `/v1/models` または起動名に合わせる） |
| `messages` | ○ | `{ "role": "system"|"user"|"assistant", "content": "…" }` の配列 |
| `stream` | ○ | 用途別。下記 |
| `max_tokens` | △ | 用途に応じて指定可。thinking ON 時は枠不足に注意 |
| `temperature` | △ | 会議定型は低め（現行 Ollama 相当 0.2 目安） |

プロンプト本文・JSON salvage・分割要約は **アプリ責務（IF 外）**。

#### stream 方針（確定）

| 用途 | `stream` | 応答の読み方 |
|------|----------|----------------|
| **会議定型**（要約・聞き漏らし・TODO・単語・スケジュール等） | **`false`** | `choices[0].message.content` を一括取得 |
| **S13 AIチャット** | **`true`** | SSE（OpenAI 互換 chunk）。`choices[0].delta.content` を連結して表示 |

会議定型で部分表示が必要になっても、初期は非 stream のままとする。

#### 非 stream 成功レスポンス（アプリが読む）

```json
{
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "本文"
      },
      "finish_reason": "stop"
    }
  ]
}
```

| 観点 | 方針 |
|------|------|
| 本文 | `choices[0].message.content`。空文字は失敗扱いしうる |
| thinking | `reasoning_content` 等だけで `content` が空は **失敗**（thinking 既定 OFF の根拠） |
| `finish_reason` | `length` は枠不足の可能性としてログ／再試行方針は実装 |

#### stream 成功時

* `data: {…}` 行の JSON を逐次パース
* `choices[0].delta.content` を蓄積
* `[DONE]` で終了
* UI は蓄積中テキストを表示してよい

#### エラー

| 状況 | アプリ |
|------|--------|
| 接続失敗・タイムアウト | AI ボタン／S13 送信をエラー表示。STT 継続 |
| HTTP 4xx／5xx | メッセージを短く表示。本文はログへ |
| サーバー再起動中 | 利用不可表示。完了後に再試行可 |

リトライは方針のみ（空応答の1回再試行等は現行 Ollama 踏襲可）。回数・秒数は実装。

## 7. 用途別クライアント契約

### 7.1 会議定型（S07 等）

| 項目 | 契約 |
|------|------|
| stream | OFF |
| messages | 主に system＋user（文字起こしスナップショット等）。詳細プロンプトはアプリ |
| 並行 | 同一サーバへ逐次または実装が決めるキュー。過負荷時は待ち表示 |
| 失敗 | 当該アシストのみ失敗。会議は継続 |

### 7.2 S13 AIチャット

| 項目 | 契約 |
|------|------|
| stream | ON |
| messages | アプリが保存する履歴＋今回入力を毎回送る（サーバ記憶に依存しない） |
| モデル | S11 と同一設定（本画面からも変更可。変更は会議定型 AI にも反映） |
| コンテキスト超過 | S13 画面仕様（70%／90%）。IF は API 形のみ |

### 7.3 スケジュール抽出

会議定型と同じ非 stream 契約。レスポンス JSON の解釈はアプリ／データ詳細。

## 8. 失敗時と生成AI OFF

| 状態 | STT | 会議定型／S13／スケジュール AI |
|------|-----|--------------------------------|
| 生成AI OFF | 可 | 不可（導線無効または説明） |
| サーバー未起動・health 失敗 | 可 | 不可。ホーム／S11／ステータスで赤字 |
| 推論エラー | 可 | 当該操作のみエラー |

| 項目 | 内容 |
